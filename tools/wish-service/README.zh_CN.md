# Passport 官网祈愿接收服务

本服务把匿名硬件事件加入**官网现有计数数据库**，不另建一套公开总数。2026-10-15已部署至 `https://www.starshoreai.com/quota-orbit/api/passport/wishes`，本开发分支默认使用此地址。硬件端到端联调仍待完成，此功能尚未进入社区版本。

## 协议与隐私

`POST /quota-orbit/api/passport/wishes`，JSON 为 `{"events":["规范UUID-v4格式", "..."]}`，每批1–32个不同编号，正文不超过2048字节。成功返回 `{"total":123,"accepted":["..."]}`。重复编号不增加总数；设备只有收到完整确认后才移除已落盘的待发前缀。不伪装网页Origin，不发送账号、个人额度、设备MAC、序列号或随机种子。

事件编号由本地随机32字节种子和序号经SHA-256派生，再设置UUID-v4版本/变体位，属于哈希派生编号，并非逐个独立随机生成。关闭同步会清除待发记录，再开启使用新种子。已计入官网的匿名次数不能按个人撤回；关闭时已有在途请求仍可能完成。

## 本地检查

在仓库根目录运行 `CC=<主机C编译器> python3 tools/wish-service/test_server.py`。测试仅用临时数据库和本机回环地址，通过编译桥接驱动固件实际C排队模型，覆盖20次点按、丢失响应后的重启重发不重复、离线3次恢复、关闭、畸形请求、并发、结构检查和限流。没有向官网写入真实计数。

要求已有 `clicks(id TEXT PRIMARY KEY, received_at INTEGER NOT NULL, version INTEGER NOT NULL)` 表，也支持可空的 `country TEXT` 列。未知列、缺失数据库或不兼容约束时拒绝写入，不做迁移。硬件记录version为2、country留空，保留网页历史与rowid游标顺序。上线前已核对生产结构、无触发器、文件权限和服务身份，在线备份通过完整性检查。公网拒绝请求检查未增加计数，未上传测试事件。

## 部署边界

候选只监听 `127.0.0.1:8970`，启动需显式传入 `--db <现有共享数据库>`。上线前先备份并核对真实共享库、验证与网页并发读写；不能指向新空库后称为同步。沿用现有计数服务的受限运行用户和数据库权限。

获准的HTTPS反向代理需把协议中的确切路由映射到回环服务，限制2KiB正文，按实际客户端网络限制每秒2次及有界突发。服务自身也按直连对端限制每秒2次、突发6次，不信任转发的客户端地址头，因此代理后的兜底桶会被所有用户共享。没有开放CORS。与网页一样，这是匿名互动次数，不是经过认证的设备数、人数或重置概率，也不宣称能彻底防刷。

接口部署后，将 `CONFIG_ORBIT_WISH_URL` 配置为获准的HTTPS地址并重新构建具体候选。不跟随跳转、不跳过证书校验；地址留空时显示“服务未就绪”，记录仅保存在设备。官网部署、具体设备刷写、提交推送与社区发布仍遵守各自授权。

## 保存与性能

使用独立 `orbit_wish` NVS命名空间保存种子和待发序号前缀，最多10,000次待发，溢出会明确提示，不假装成功。网络工作线程超时6秒，失败退避最高32秒；按键回调不写Flash。近期点按合并落盘，突然断电、64项内存输入队列满或存储失败仍可能丢失部分近期记录，不承诺无限连按或掉电零丢失。声音、绘制与网络同时运行的表现尚需真机复验。现有Wi-Fi、Mac配对及提示音设置位于其他命名空间或键，不改其存储。
